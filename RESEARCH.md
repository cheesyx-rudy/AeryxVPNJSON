# Research notes — AeryxJSON-Parser

Обзор технических решений на 27 октября 2026 года. Исследование не означает, что запуск на реальных источниках уже состоялся; живой запуск возможен только после добавления пользовательских URL в `sources.txt` и выполнения GitHub Actions.

## Подходы, использованные в проекте

| Проект / документ | Что подтверждает | Применение здесь |
|---|---|---|
| sing-box `URLTest` — https://sing-box.sagernet.org/configuration/outbound/urltest/ | Нативный outbound принимает список других outbound'ов, URL проверки, интервал и допуск задержки | Основной профиль страны использует один `urltest` outbound как `route.final`; клиент сам выбирает лучший узел по собственным результатам |
| Xray Project X Routing — https://xtls.github.io/en/config/routing.html | Балансировщик `leastPing` выбирает узел по результатам наблюдения; для этой стратегии нужен observatory | Дополнительный Xray JSON создаёт `observatory`, `balancers`, `selector` и `fallbackTag` вместе, а не публикует одинокий `leastPing` |
| Remnawave XRAY_JSON advanced — https://github.com/remnawave/panel/blob/main/docs/learn/xray-json-advanced.md | Xray JSON-профиль может включать outbounds, balancer, наблюдатель и правила routing как полная клиентская конфигурация | Выход Xray — полноценный JSON профиль, а не невалидный массив URI, замаскированный под JSON |
| `xray-checker` — https://github.com/kutovoys/xray-checker | Раздельная реальная проверка узлов через Xray и структурированные результаты/метрики | Используем действующую проверочную основу предыдущего parser, а в output допускаем только записи с успешным `proxy_ok*` status |
| DB-IP Lite — https://db-ip.com/db/download/ip-to-country-lite | Локальная база сопоставляет публичный IP со страной; GeoIP требует периодического обновления и атрибуции | Страна резолвится локально через MMDB, затем используется подпись как запасной вариант; неизвестная страна не публикуется |
| GitHub Actions docs — https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule | Cron workflow может запускаться с задержкой | Schedule остаётся автоматическим механизмом обновления, но README не обещает точную минуту запуска |

## Архитектура вывода

1. Сначала текущий проверочный pipeline получает и разбирает URI, YAML/JSON, выполняет фильтрацию и проверяет узлы реальным туннелем.
2. В генератор передаётся только `output/engine/parsed_proxies.json` после успешного шага pipeline. Генератор дополнительно требует `check_status` с префиксом `proxy_ok`.
3. Страна берётся из уже нормализованной метки, которую поставил GeoIP resolver. Для неизвестной страны нет автоматического добавления в произвольный регион.
4. Для каждого country code создаётся отдельный `countries/{CODE}.json`, формат — native sing-box config. Каждому узлу назначается уникальный tag, а `urltest` проверяет узлы группы и становится `route.final`.
5. Параллельно создаётся `xray/{CODE}.json`, но только с URI, которые умеет представлять `build_xray_config`. Xray `leastPing` вместе с `observatory` выбирает узел по результатам измерений; неподдержанные Xray протоколы остаются доступны в sing-box JSON.
6. `index.json` содержит metadata-only каталог. `country-metadata/{CODE}.json` хранит метаданные и checksum профилей. Не добавляем произвольный `metadata` ключ в клиентские профили, поскольку он не относится к схеме sing-box/Xray.
7. Workflow проверяет каждый файл нативным ядром в staging tree и только затем синхронизирует страны в открытый репозиторий. Пустые входы, слишком маленькая выборка или невалидный профиль не должны заменять ранее опубликованные файлы.

## Балансировщик — что он гарантирует и что нет

- sing-box `urltest` — клиентский выбор по указанному тестовому URL, а не гарантия максимальной реальной скорости загрузки для любого сайта. Пользовательская сеть/маршрут влияет на измерения.
- Xray `leastPing` опирается на observatory, а не только на наличие outbound в JSON.
- Здесь нет серверной телеметрии каждого клиента. Генератор не знает пользовательские задержки; решение принимает импортированный клиент. Тестовый URL и интервал можно поменять в `config/settings.yaml`.

## Ограничения

- Формат JSON не является универсальным для всех VPN-клиентов. `countries/*.json` — sing-box; `xray/*.json` — Xray. Пользователь должен импортировать профиль в совместимый клиент.
- Невозможно сохранить каждый неизвестный panel-specific вариант при конвертации в другую схему, если схема получателя не имеет соответствующих полей. Неуспешные конвертации записываются агрегированно без URI/секретов в отчёт генератора.
- Схемы и тесты проверяют структуру, правильную ссылочную целостность и интеграцию, но живую совместимость с узлом можно подтвердить только во время GitHub Actions.
- Публичный GitHub repo делает содержимое `countries/*.json` и `xray/*.json` доступным любому. Туда следует публиковать только узлы, которые можно раскрывать публично.
