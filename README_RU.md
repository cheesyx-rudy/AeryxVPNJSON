# AeryxJSON-Parser

Отдельный парсер для открытого GitHub-репозитория, который публикует **одну подписку `AeryxVPN.json` в формате Happ/Xray JSON array**. Это не нативный sing-box JSON и не набор отдельных файлов по странам.

## Как выглядит результат

Корневой `AeryxVPN.json` — массив полноценных Xray-конфигураций. Каждый элемент массива отображается в Happ как отдельная строка:

- `🇩🇪 Германия` — профиль только с узлами, определёнными как Германия;
- `🇳🇱 Нидерланды` — профиль только с узлами Нидерландов;
- `🇪🇺 Автовыбор` — общий профиль со всеми опубликованными узлами.

Названия формируются по стране: известные страны получают русские названия, для остальных используется исходное название из базы геолокации. Видимое имя задаётся через `remarks`. Структура каждого элемента строится на общем шаблоне `config/xray-profile-template.json`, который основан на предоставленных рабочих примерах Happ. В шаблоне сохраняется `meta: null`, как и в образцах.

## Балансировка и проверка

В каждом country-профиле и Auto-профиле используются:

- `burstObservatory` с настройками `connectivity`, `destination`, `interval`, `sampling` и `timeout` из эталонного формата;
- теги узлов `proxy-1`, `proxy-2`, ...; селектор `proxy` сопоставляет весь этот префикс;
- `routing.balancers` с тегом `balancer` и стратегией `leastPing`;
- набор правил маршрутизации из общего шаблона, включая исключения для direct/block и финальную маршрутизацию TCP/UDP через балансировщик;
- четыре inbound: SOCKS `127.0.0.1:10808`, HTTP `127.0.0.1:10809`, `metrics_in` и `api_in`.

Проверка задержки не гарантирует полноценное TLS/REALITY-рукопожатие для каждого сайта. Поэтому парсер включает только узлы, прошедшие туннельную проверку и конвертацию в поддерживаемый Xray outbound. TUIC, AnyTLS, SSR и Hysteria v1 пропускаются: этот генератор не превращает их в другой протокол молча.

Общие параметры DNS, API, статистики, политики и маршрутизации хранятся в `config/xray-profile-template.json`, а не дублируются вручную в разных ветках генератора. При изменении эталонного профиля нужно обновлять именно этот шаблон и соответствующие структурные тесты.

## Важное отличие от обычной URI-подписки

Happ трактует JSON-массив как набор полных Xray-профилей. Для JSON-конфигураций передаются непосредственно заданные правила Xray; привычные правила маршрутизации Happ могут не применяться. Необходимо учитывать это при настройке маршрутизации внутри каждого профиля. См. [официальные примеры JSON в документации Happ](https://www.happ.su/main/dev-docs/examples-of-links-and-parameters).

## Источники и публикация

1. Добавляй URL в `sources.txt`, по одному на строку. Комментарии начинаются с `#`. Для источников с секретами используй переменные окружения GitHub Actions, а не публикуй токены в открытом репозитории.
2. GitHub Actions загружает источники, разбирает ссылки и структурированные JSON/YAML, фильтрует записи, проверяет узлы и определяет страны.
3. Генератор собирает профили стран и общий Auto-профиль в один JSON-массив.
4. В workflow каждый профиль проверяется актуальным официальным Xray-core командой `xray run -test -config ...`. Из проверки удаляются только поля интерфейса Happ (`remarks`, `meta`), которые сам Xray не должен читать.
5. Только после успешной проверки публикуются `AeryxVPN.json` и `AeryxVPN.metadata.json`. Диагностический `build-report.json` загружается как артефакт и не коммитится.

Единственный URL подписки после публикации:

```text
https://raw.githubusercontent.com/OWNER/REPO/main/AeryxVPN.json
```

`AeryxVPN.metadata.json` — справочный файл со счётчиками, временем сборки и SHA-256. Его не нужно импортировать в клиент.

## Автоматический запуск

Workflow `.github/workflows/update-json.yml` запускается:

- каждые 6 часов;
- после изменений источников, настроек, кода или тестов;
- вручную в разделе **Actions → AeryxVPN Happ JSON-array subscription → Run workflow**.

Для пуша используется встроенный `GITHUB_TOKEN` с `contents: write`, отдельный токен не нужен. Расписание GitHub Actions может задерживаться при нагрузке; точное время старта не гарантируется.

## Локальные проверки разработчика

Для офлайн-тестов:

```bash
python -m pip install -e .
python -m unittest discover -s tests -v
```

Для проверки готового результата после установки официального Xray-core:

```bash
python tools/validate_outputs.py --root output/publish --xray tools/xray
```

Без реальных источников и живого запуска нельзя утверждать, что каждый узел работает. Офлайн-тесты проверяют преобразование форматов и целостность конфигурации; реальное подключение требует проверки через туннель.

## Публичные данные

`AeryxVPN.json` содержит параметры подключения к серверам, включая учётные данные протоколов. В публичный репозиторий допустимо публиковать только источники, владельцы которых разрешают открытое распространение конфигураций.
