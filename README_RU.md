# AeryxJSON-Parser

Отдельный парсер AeryxVPN для **country-split JSON-подписок**. Он запускается только в GitHub Actions; локально на ПК ничего запускать не нужно. Результаты публикуются в том же открытом репозитории, где находятся код и `sources.txt` — отдельный токен для публикации не требуется.

## Что публикуется

| Файл / каталог | Назначение |
|---|---|
| `index.json` | Главный каталог подписки: метаданные, время обновления, число стран и конфигов, ссылки на отдельные профили |
| `countries/DE.json`, `countries/US.json`, … | Полные клиентские конфигурации sing-box — одна страна на файл |
| `xray/DE.json`, `xray/US.json`, … | Полные конфигурации Xray для той части узлов, которую Xray может представить |
| `country-metadata/DE.json`, … | Метаданные конкретной страны, контрольные суммы файлов и параметры балансировщиков |
| `sources.txt` | Единственный основной файл, который нужно редактировать, чтобы добавлять источники |
| `config/settings.yaml` | Таймауты, фильтрация, проверки, GeoIP, расписание в метаданных и балансировщики |

**Не все страны попадают в один файл.** Например, Германия окажется в `countries/DE.json`, Нидерланды — в `countries/NL.json`, а `index.json` только перечисляет группы и ссылки на них. Страна определяется движком по GeoIP базе DB-IP Lite, а подпись в имени используется как запасной источник. Если страну нельзя определить, узел не публикуется в неопределённую группу.

## Как добавлять источники

В `sources.txt` добавляй **один URL на строку**. Пустые строки и комментарии, начинающиеся с `#` или `;`, игнорируются.

```text
https://example.org/subscription.txt
https://example.org/clash.yaml
https://example.org/sing-box.json
https://panel.example/api/subscription | User-Agent: Happ/4.7.1/Android | X-Client: Android
```

Поддерживаются обычные URI-подписки и Base64, VLESS, VMess, Trojan, Shadowsocks, SSR (если валидатор может представить протокол), Hysteria/Hysteria2, TUIC, AnyTLS, SOCKS/HTTP, Clash/Mihomo YAML, sing-box JSON, Xray JSON и доступные веб-страницы со ссылками на конфиги. Конкретные ограничения адаптеров учитываются: конвертация не должна молча придумывать отсутствующие параметры.

### Заголовки и закрытые источники

Дополнительные HTTP-заголовки указываются через `|`:

```text
https://panel.example/sub | User-Agent: Happ/4.7.1/Android | Authorization: Bearer ${PANEL_TOKEN}
```

Значение `${PANEL_TOKEN}` подставится из GitHub Actions Secret `PANEL_TOKEN`. Для других переменных добавь секрет в Settings → Secrets and variables → Actions, а переменную окружения — в `.github/workflows/update-json.yml`. **Не записывай токены в открытый `sources.txt`.**

Важно: репозиторий публичный. Опубликованные конфигурации неизбежно содержат параметры подключения/учётные данные самих VPN-узлов. Добавляй только источники, конфиги которых можно распространять публично. Токены скачивания в GitHub Secrets не скрывают сами опубликованные параметры прокси.

## Как работает проверка

Парсер использует основу уже подготовленного AeryxParser: загрузка источников параллельно, разбор форматов, нормализация и дедупликация, DNS/IP/CIDR-фильтрация, GeoIP и проверка узлов через официальные Xray-core и sing-box. В JSON попадают только записи со статусом успешной туннельной проверки `proxy_ok*`; один открытый TCP-порт, только корректный синтаксис или непроверенный узел не означают, что конфиг рабочий.

Перед публикацией:

1. Выполняются офлайн-тесты кода.
2. Скачиваются GeoIP база и официальные бинарники ядер.
3. Собираются и проверяются кандидаты через реальные туннели.
4. Валидатор преобразует принятые записи в отдельные профили стран.
5. Каждый sing-box JSON проверяется командой `sing-box check -c`, каждый Xray JSON — `xray run -test -config`.
6. Только после успешной валидации результат коммитится в этот репозиторий.

Промежуточные отчёты и логи проверки хранятся как артефакты GitHub Actions, не коммитятся в открытый репозиторий и не содержат полный список отклонённых URI. Если входных/принятых узлов меньше минимального порога, обновление останавливается и старые опубликованные JSON остаются без изменений.

## Балансировщики

### sing-box — основной JSON-формат

В `countries/{CODE}.json` содержатся все поддержанные и прошедшие проверку узлы страны. В конце `outbounds` добавляется нативный `urltest` outbound, а `route.final` указывает на него. Клиент периодически проверяет доступность узлов по `https://www.gstatic.com/generate_204` и выбирает наиболее быстрый согласно результатам измерения и `tolerance`.

Настройки по умолчанию (`config/settings.yaml`): проверка раз в `3m`, допуск переключения `80` миллисекунд. Это **клиентский балансировщик**, а не серверная раздача трафика: решение принимается на устройстве пользователя по его собственному маршруту.

### Xray — дополнительный JSON-формат

В `xray/{CODE}.json` создаются outbound'ы, которые умеет представить Xray, и балансировщик `leastPing`. Результаты собираются `observatory` через ту же выборку тегов. Поэтому `leastPing` не оставлен без наблюдателя. Hysteria/Hysteria2, TUIC и AnyTLS не включаются в Xray-конфиг, если адаптер Xray не умеет их представить; они остаются в sing-box-конфиге. В `index.json` для каждой страны есть фактический счётчик Xray-совместимых узлов.

## Метаданные

У каждого запуска автоматически обновляются `generated_at`, локальное время, часовой пояс, ссылки поддержки и проекта, интервал обновления, количество стран и проверенных конфигов. Главные метаданные находятся в `index.json`; метаданные отдельной страны — в `country-metadata/{CODE}.json`.

Произвольное поле `metadata` намеренно не добавляется в клиентский sing-box/Xray конфиг: это не стандартная часть схемы этих клиентов и может привести к отклонению файла. Вместо этого ссылка из главного каталога ведёт на нативный профиль, а рядом лежит метаданный sidecar JSON.

## Как получить URL

После первого успешного запуска открой `index.json` и найди нужную страну. Для открытого репозитория raw-ссылки имеют вид:

- Каталог: `https://raw.githubusercontent.com/OWNER/REPO/main/index.json`
- sing-box Germany: `https://raw.githubusercontent.com/OWNER/REPO/main/countries/DE.json`
- Xray Germany: `https://raw.githubusercontent.com/OWNER/REPO/main/xray/DE.json`
- Метаданные Germany: `https://raw.githubusercontent.com/OWNER/REPO/main/country-metadata/DE.json`

Замени `OWNER/REPO` на фактический адрес нового репозитория. `index.json` — каталог и метаданные, его не следует импортировать как клиентскую конфигурацию. Импортируй файл конкретной страны в формате, подходящем твоему клиенту.

## GitHub Actions

Workflow находится в `.github/workflows/update-json.yml` и запускается:

- каждые 6 часов (`17 */6 * * *`);
- после изменения источников, кода или настроек;
- вручную в Actions → **AeryxJSON country subscriptions** → Run workflow.

Он использует встроенный `GITHUB_TOKEN` с `contents: write` и публикует результаты в этот же репозиторий. Секрет для отдельного репозитория не требуется. Если `sources.txt` пуст, workflow запускает офлайн-тесты и корректно пропускает генерацию, не меняя текущие JSON. Расписания GitHub Actions могут задерживаться при высокой нагрузке; cron не гарантирует точное время запуска.

## Артефакты диагностики

Открой Actions → последний запуск → Artifacts → `aeryxjson-build-report`. Там будут сводный отчёт валидации, счётчики стадий и сводка генератора. В репозиторий не попадают диагностические файлы с приватными URI.

## Источники и технические ориентиры

- [sing-box URLTest](https://sing-box.sagernet.org/configuration/outbound/urltest/) — штатный выбор узла по измерениям доступности/задержки.
- [Xray Project X — Routing / Balancers](https://xtls.github.io/en/config/routing.html) — `leastPing`, `fallbackTag`, `selector` и требования к observatory.
- [Xray Checker](https://github.com/kutovoys/xray-checker) — реальная проверка прокси через Xray и сбор отдельных результатов.
- [DB-IP Lite](https://db-ip.com/db/download/ip-to-country-lite) — локальная GeoIP-база. DB-IP Lite публикуется на условиях CC BY 4.0; атрибуция нужна при распространении данных.
- [actions/checkout](https://github.com/actions/checkout/releases), [actions/setup-python](https://github.com/actions/setup-python/releases), [actions/upload-artifact](https://github.com/actions/upload-artifact/releases) — версии GitHub Actions, применённые в workflow.
