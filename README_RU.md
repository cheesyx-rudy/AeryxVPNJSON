# AeryxVPN JSON Parser

**Текущий релиз:** 1.0.0  
**Движок проверки:** AeryxVPN Core 0.8.0 (закреплённый commit SHA)

Парсер собирает источники подписок, извлекает и удаляет точные дубликаты share-ссылок, разрешает IP-адреса серверов, проверяет прокси-туннели через Xray/sing-box и формирует Happ-совместимый JSON-массив `AeryxVPN.json`.

## Проверка IP и подсетей

По умолчанию используются специализированные списки адресов и подсетей:

- AntiFilter resolved IP: `ipresolve.lst`
- AntiFilter subnet: `subnet.lst`
- Re-filter: `ipsum.lst`
- AntiFilter community: `community.lst`

Каждый источник скачивается отдельно и кэшируется. Срок кэша по умолчанию — 72 часа. Слишком широкие внешние диапазоны IPv4 крупнее /24 и IPv6 крупнее /48 по умолчанию игнорируются: это снижает риск случайно выкинуть целые сети дата-центров и CDN. Собственные CIDR можно указывать в `config/manual-deny-cidrs.txt`.

Совпадение с публичным IP/CIDR-списком сначала фиксируется в диагностике, а не удаляет узел до проверки туннеля. В режиме proxy в подписку попадают только конфигурации, для которых Xray/sing-box подтвердил работу туннеля. Совпадение с denylist не отменяет успешную проверку: рабочий публичный узел сохраняется. Если совпавший узел не прошёл проверку туннеля, он отклоняется с указанием причины и CIDR. Адреса, у которых все DNS-ответы являются частными, loopback, link-local или другими non-global адресами, не попадают в публичную подписку.

Режимы tcp и none предназначены для диагностики и не могут автоматически заменить итоговую подписку: без положительной проверки туннеля нужна явная настройка `force_publish`. Для checkout приватного Core в GitHub Actions настрой секрет `AERYX_CORE_READ_TOKEN` с правами только на чтение репозитория `cheesyx-rudy/AeryxVPN-Core`.

## Геолокация

Сначала используется локальная GeoIP-база, затем подписи источника/конфига и поддерживаемые доменные зоны стран. Если страну достоверно определить нельзя, проверенный узел помещается в отдельный профиль `ZZ` / «Не определена», а не помечается как Европа и не удаляется только из-за отсутствия геолокации.

## Отчёты и безопасность

Основной отчёт: `output/engine/validation_report.json`. В нём сохраняются статусы источников, использование кэша, совпавшие CIDR, результаты проверки и причины отклонения. Не публикуйте необработанные URI подписок и данные доступа.

Pull Request запускает только offline-тесты. Полная генерация и публикация действующей подписки не запускается при каждом PR; live-процесс остаётся отдельным ручным запуском workflow.
