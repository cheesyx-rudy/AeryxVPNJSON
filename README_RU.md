# AeryxVPN Core

Общая Python-библиотека для URI- и JSON-парсеров AeryxVPN.

> **Статус: `0.2.0` — общие входные адаптеры готовы, проверки ещё переносятся.** Core уже
> извлекает URI-подписки и разбирает Xray JSON, sing-box JSON, Clash JSON/YAML и SIP008.
> Производственные проверки через Xray/sing-box пока не перенесены; не заменяйте им
> существующие pipeline парсеров.

## Архитектура

- **Входные адаптеры** преобразуют share URI, Xray JSON, sing-box JSON, Clash JSON/YAML и SIP008 в `ProxyCandidate`.
- **Validation Engine** направляет конфигурацию валидатору соответствующего протокола.
- **Выходные адаптеры** сохраняют контракты проектов: обычные share links для URI-парсера
  и существующую Happ-совместимую JSON-схему для JSON-парсера.
- **SourcePayload** хранит исходные данные, чтобы неизвестные поля JSON не терялись при
  преобразовании.

Core запускается как библиотека непосредственно внутри GitHub-hosted Actions runner.
Это не постоянно работающий сервер, демон или HTTP API.

## Локальная разработка

```bash
python -m pip install -e '.[dev]'
python -m pytest -q
python -m ruff check .
```

## Версионирование

Workflow парсеров должен подключать конкретный релиз Core, например `v0.2.0`, а не ветку
`main`. После стабилизации публичного API несовместимые изменения оформляются новой major-версией.

## Доступ к приватному репозиторию

Поскольку JSON-парсер публичный, его workflow должен получать Core через отдельный
read-only секрет GitHub Actions с минимальными правами и доступом только к репозиторию Core.
Нельзя записывать токен в исходники, YAML, URL, артефакты или логи. Не передавайте секрет
workflow, запущенным из недоверенных pull request.


## Релиз 1.0.0

JSON-парсер использует AeryxVPN Core 0.8.0 для проверки прокси через Xray/sing-box
и HTTP-проверки через локальный SOCKS-туннель. Существующий сборщик Happ JSON-массива
остаётся ответственным за выходной формат: результаты Core не пересобирают JSON
и не удаляют неизвестные поля профилей.

Workflow закрепляет версию Core, проверяет установленный wheel, запускает тесты,
а затем выполняет сборку. Для checkout приватного Core нужен read-only секрет
GitHub Actions `AERYX_CORE_READ_TOKEN`.
